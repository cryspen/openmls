* Overview

This directory holds the Lean 4 / [[https://github.com/AeneasVerif/aeneas][Aeneas]] proof development for the *ratchet-tree math* of
OpenMLS (RFC 9420 §4 / Appendix C, ported to Rust in
=openmls/src/binary_tree/array_representation/treemath.rs=).

The Rust functions are extracted to LLBC by Charon and to Lean by Aeneas; we then discharge,
in Lean, the *panic-freedom* proof obligations Aeneas generates (each function is total /
never panics on its stated precondition), plus a few functional postconditions.

* Status: GREEN

- All *9 / 9* =*.spec.proof= obligations are proved.
- The proof files themselves contain *no =sorry=*.
- The only admitted facts are *11 trusted =@[spec]= contracts* for opaque standard-library
  operations Charon could not extract — the entire audit surface, collected in one file
  (=AdmittedCoreSpecs.lean=).

Authoritative gate (run from this directory):

#+begin_src sh
lake build Openmls.Proofs.Proofs
#+end_src

The LSP can disagree with the build mid-edit; trust =lake build=. A full build also emits 4
=sorry= warnings from upstream =Aeneas/Std/*= — those are not ours.

* Module layout

Hand-written proof modules under =Openmls/Proofs/=, import DAG
=Common ← {BitMath, MissingCoreSpecs, AdmittedCoreSpecs} ← Proofs=:

| File                   | Concern                                                      | Real =sorry= |
|------------------------+--------------------------------------------------------------+------------|
| =Common.lean=            | generic loop driver =loop_spec_measure= + triple helpers,      |          0 |
|                        | =vecLen=/=vecLen_eq_length=, =attribute [spec] uncurry=          |            |
| =BitMath.lean=           | pure-=Nat= =tones= / =parent= bit-arithmetic lemmas                |          0 |
| =MissingCoreSpecs.lean=  | PROVED =@[spec]= contracts for =core=/=alloc= ops                |          0 |
| =AdmittedCoreSpecs.lean= | TRUSTED audit surface: 11 admitted =@[spec]= core contracts    |         11 |
| =Proofs.lean=            | per-function treemath value/helper specs + the 9 obligations |          0 |

=Common.lean= registers =attribute [spec] uncurry= once; it propagates to all importers (needed
so =mvcgen= steps Aeneas tuple-destructuring binds). Ordering constraint that must be preserved:
=direct_path.spec.proof= must elaborate before =common_direct_path.spec.proof= (both in
=Proofs.lean=, kept in that order).

* The 9 obligations (all proved, in =Proofs.lean=)

=level=, =root=, =left=, =right=, =is_node_in_tree=, =lowest_common_ancestor=, =direct_path=,
=common_direct_path=, =copath=.

Each loop goes through the generic =loop_spec_measure= (mvcgen-steppable body obligation) via a
per-function =*_loop_spec= helper (=level_loop_spec=, =direct_path_loop_spec=, =lca_loop0_spec=,
=common_direct_path_loop_spec=). No proof still uses the raw =Aeneas.Std.loop.spec_decr_nat=.

* Trusted audit surface (=AdmittedCoreSpecs.lean=)

The 11 admitted contracts are the =@[spec]= statements for the bare =axiom=s in
=Openmls/Extraction/FunsExternal.lean= (operations Charon could not extract). Every one is stated
purely over =core=/=alloc= — *no treemath symbols leak in*:

- Vec/slice: =deref_mut_slice_spec=, =reverse_slice_spec=, =vec_index_spec=, =vec_push_spec=,
  =min_usize_spec=, =u32_cmp_spec=
- iterators: =sharedavec_into_iter_spec=, =slice_iter_next_spec=, =vec_is_empty_spec=,
  =vec_pop_spec=, and the generic =into_map_collect_spec= (its =sibling= instance is *proved*,
  not admitted, in =Proofs.lean=)

Plus the opaque model =sliceIterElems=. The three *proved* core specs (=vec_len_spec=,
=vec_new_spec=, =vec_with_capacity_spec=) live separately in =MissingCoreSpecs.lean= so the audit
surface stays exactly the admitted set.

* Rust-side specs (backporting)

Some Lean postconditions have been backported to the Rust source as =hax_lib= annotations, so the
spec travels with the code and becomes the extracted =.pre=/=.post=.

Already native (pre-existing source annotations):
- =level= — =result ≤ 31 && (result == 0) == ((index & 1) == 0)=
- =is_node_in_tree= — =result == (node_index.u32() < size.u32())=

Backported in this effort (=treemath.rs=):
- =ParentNodeIndex::to_tree_index= — =requires(self.u32() < 2^31)=, =ensures(result == 2*self.u32()+1)=
- =TreeNodeIndex::new= — =ensures(result.u32() == index)= (round-trip)
- =direct_path= — =ensures(result.len() <= 30 && ∀ i, 2*result[i].u32()+1 < 2^31-1)=

Not backported — see TODO for the reasons.

*Caveat:* the Rust edits compile (=cargo check -p openmls --lib=) but have *not* been re-extracted,
so their effect on the generated =.pre=/=.post= and the Lean proofs is unverified. Notably
=to_tree_index='s new =requires= ripples to every caller, and =direct_path='s =forall= clause is
the one most likely to need adjustment.
