** Module layout

Hand-written proof modules under =Openmls/Proofs/=, import DAG
=Common ← BitMath ← MissingCoreSpecs ← PartialSpecs ← PureSpecs ← Proofs ← Verification=
(=PartialSpecs= imports BitMath *and* MissingCoreSpecs):

| File                   | Concern                                                                                               |
|------------------------+-------------------------------------------------------------------------------------------------------|
| =Common.lean=            | generic loop driver =loop_spec_measure= + triple helpers, =vecLen=, =sliceIterElems=                        |
| =BitMath.lean=           | pure-=Nat=/u32 bit lemmas (=tones=, parent/left/right value arithmetic); =scalar_tac=/=simp= registrations |
| =MissingCoreSpecs.lean=  | PROVED =@[spec]= contracts for =core=/=alloc= ops, discharged against the upstream CoreModels bodies      |
| =PartialSpecs.lean=      | hand-written mvcgen/partial-correctness triples for the extracted helpers + combinators               |
| =PureSpecs.lean=         | value triples for the verification-transparent fns; monadic helpers; pure companion lemmas            |
| =Proofs.lean=            | the 19 obligations, loop specs, =level.spec_pure=/=parent.spec_value=/=direct_path.spec_pure=           |
| =Verification.lean=      | the mechanized statement freeze: 19 =<fn>.spec.conformance= theorems (definitional, no attributes)      |

** The proof scheme

- *One theorem per obligation.* =Proofs.lean='s theorem statements correspond 1:1 to the
  generated =<fn>.spec= Props in =Openmls/Extraction/Specs.lean=; the correspondence is
  *machine-checked* by =Openmls/Proofs/Verification.lean= (a conformance theorem per
  obligation, proved by definitional unfolding — a re-extraction that changes a spec breaks
  it at elaboration). =Openmls/Extraction/ProofObligationsExplicit.lean= remains as a
  hand-derived *readable view* only (not imported; proofs stay =sorry=).
- *Stepping* is done by =hax_mvcgen= (fallback: plain =mvcgen= + local massaging at spans where
  it misbehaves). After stepping, residual goals must be pure scalar/bit arithmetic.
- *Loop invariants* are stated separately, one =*_loop_spec= theorem per loop via the generic
  =loop_spec_measure= driver in =Common.lean=.
- *Pure-spec exception (validated):* some official posts are too costly/weak to consume at
  call sites; validated companion specs fill the gap — =level.spec_pure= (registered; =level=
  carries no obligation of its own), =parent.spec_value=, =root.spec_value= and
  =direct_path.spec_pure= (unregistered, consumed by hand or via mvcgen's erasure
  =- <official>.spec.proof= at call sites).
  New pure specs require explicit user validation, case by case.
- *Sorry style:* a remaining =sorry= sits under its own explicit bullet / =case= block with a
  =-- TODO(arith): …= comment; a bare =all_goals sorry= is allowed only when *every* remaining
  goal is sorried. No =sorry= may hide inside a =first | … | sorry= chain, and no goal
  containing a Hoare triple / =wp⟦…⟧= may be sorried (that indicates broken stepping).
